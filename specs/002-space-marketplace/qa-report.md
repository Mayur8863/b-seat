# QA report: spec 002 space marketplace (integration pass 1)

Branch `qa/002-integration` (merged with `dev/002-integration` at 5cb40bf, which contains the U01-U05 fix).
Date 2026-10-28. Method: automated suites, then scripted exploratory runs in the Playwright container
(desktop 1280 and 1920, mobile 375, axe WCAG 2.1 AA on every visited page), API probes for rules and
ownership, and Mailpit inspection. The Playwright MCP browser was not available to this agent, so the
exploratory runs used throw-away scripts (`apps/web/e2e/zz-*.spec.ts`, not committed) driving the same Chromium.
Screenshots: `/tmp/claude-1000/-home-a55-55-55-BSeat/1c45bb4b-9da0-4f0c-9f64-1269fd2144ab/scratchpad/qa/`.

## Verdict

Core P1 flows work end to end: owner lists a space, adds seats, sets prices, publishes; a renter finds it, books a
pass, sees it in My bookings, the owner sees the booking, the renter cancels and the seat is free again. Rules and
ownership checks behave as specified (see "What passed"). Open items are mostly mobile layout, one accessibility
violation, a search-form state bug and a tooling gap (10 open, QA-07 withdrawn). No data-integrity or authorization defects found.

### Flaky tests and root causes

- `listing-results.test.tsx` "paging: appends the next page, focuses its first card": fails in the parallel `check`
  run, passes alone and in the serial run (3 s). It asserts focus inside `vi.waitFor`, whose default 1 s budget is
  too short when jsdom and MSW are starved by parallel workers. Not a product bug. Fix by passing a larger timeout
  to that `waitFor` (test code, dev-owned) or by reducing worker count for the web package. The earlier `space-form.test.tsx`
  timeout did not recur in this run, same class of cause (CPU contention).
- The 2 email tests are deterministic, not flaky: see QA-09.

## What passed (no defect found)

- US1: sign-up needs a role (error shown, axe clean); owner and renter land on role-specific dashboards with links to all pages; renter preferences prefill Find; owner nav includes List a space; guests are redirected to `/sign-in?next=`; `/book` redirects to `/find`; a renter on an owner page sees "Owners only".
- US2: create-space validation lists 9 fields with `aria-invalid` and described-by errors; time zone is suggested from the country; publish without seats or prices is refused with what is missing; duplicate seat label shows a field error; bulk pattern shows "Adds 4 seats: B-1 to B-4".
- US3: day, night and 24-hour slots; prices saved ("Prices saved"); negative price rejected with an error; 24-hour saving shown on the renter page (for example "Save 5.00 (17%)").
- US4: search by country and city (case and trim insensitive), empty state offers "Search all of United Kingdom", listing, pass, date, seat, confirm dialog, confirmation with payment note; API refuses: own space (422), second overlapping booking (409), 24-hour over day (409), start more than 30 days ahead (422), past start (422), pass not offered (422), unknown seat (404), unpublished space (404 for renters). Emails to renter and owner state "Payment is made directly to the owner", period in space time zone.
- US5/US6: occupancy over a booking returns 409 with the conflicting dates; the private note is not in the renter seat view; a calendar change reports `bookingsOutsideCalendar` and keeps bookings.
- US7: renter sees the booking, owner sees it with name and email, cancel frees the seat; another user cancelling gets 404; owner cancelling a renter booking gets 404.
- Ownership: another owner gets 404 on get, seats, bookings and unpublish; a renter gets 403 on owner API.
- Axe: zero violations on sign-up, create space, seats, pricing, availability, bookings, find, listing, confirm dialog, booked, My bookings and dashboards at 1280, 1920 and 375 (except QA-02).
