# Data model: Space photos (003)

Approved by the architect on 2026-10-28 (T001), with the amendments marked **(T001)**. The decisions and their
reasons are in [ADR-0011](../../docs/adr/0011-space-photo-storage.md).

The Drizzle schema goes in `apps/api/src/db/schema/photo.ts` (one file for the photo aggregate) and is exported
from `schema/index.ts`. T005 adds one generated migration. If drizzle-kit cannot express the deferrable unique
constraint, a `--custom` migration follows right after it and recreates the constraint as `DEFERRABLE INITIALLY
IMMEDIATE`, under the same name. That is the same pattern as the 002 exclusion constraints, and the Drizzle
schema still declares the unique, so `db:generate` stays drift-free. Domain tables use `uuid` ids and
`timestamptz`. Nothing in 002's tables changes, so the migration is purely additive (expand only; nothing to
contract later).

## `space_photo`

One fully added photo of one space. A row exists only after the image has been validated, processed and written
to storage (FR-006). In-flight uploads have no row.

| Column           | Type          | Null | Default | Notes                                                                                       |
| ---------------- | ------------- | ---- | ------- | ------------------------------------------------------------------------------------------- |
| `id`             | `uuid`        | no   |         | PK. Generated by the API **before** the objects are written, because it is part of the keys |
| `space_id`       | `uuid`        | no   |         | FK → `space(id)` `ON DELETE RESTRICT` (spaces are never deleted, 002)                       |
| `position`       | `smallint`    | no   |         | 1 = cover. Exactly 1..n per space (service rule, ADR-0011 section 7)                        |
| `description`    | `text`        | yes  |         | Plain text, 1–150 characters after trimming. `NULL` means none (R-8)                        |
| `display_width`  | `integer`     | no   |         | Pixel size of the `display` variant, used for layout without shift (R-10)                   |
| `display_height` | `integer`     | no   |         |                                                                                             |
| `created_at`     | `timestamptz` | no   | `now()` |                                                                                             |
| `updated_at`     | `timestamptz` | no   | `now()` | Set by the service on describe and reorder                                                  |

**(T001)** `byte_size` is dropped. No query or requirement reads it, and the `photo.added` log already carries
`bytesStored`. The `card` variant is **always 640 × 480** (ADR-0011 section 4: the card may upscale), so its size
is a constant, not a column.

**Constraints** (constitution IV):

- `space_photo_position_range` CHECK `(position BETWEEN 1 AND 10)`.
- `space_photo_position_unique` UNIQUE `(space_id, position)` **DEFERRABLE INITIALLY IMMEDIATE**. Together with the
  range check, it means a space can never have more than 10 photos (FR-002, SC-006).
  - **(T001)** The constraint is deferrable so that it is checked at the **end of each statement** rather than row
    by row. Reorder and the renumber after a delete are each **one `UPDATE` statement**, and no code calls
    `SET CONSTRAINTS`.
  - A non-deferrable unique can fail inside a single permuting `UPDATE`, and the 1–10 CHECK rules out the
    "move rows out of range first" workaround.
- `space_photo_description_length` CHECK `(description IS NULL OR char_length(description) BETWEEN 1 AND 150)`.
- `space_photo_display_size_positive` CHECK `(display_width > 0 AND display_height > 0)`.

**Indexes**: the unique constraint's index on `(space_id, position)` serves every read:

- the owner list and the listing gallery (`WHERE space_id = $1 ORDER BY position`);
- the search cover join (`space_id = s.id AND position = 1`).

No other index is needed.

**Not in the database**: gap-free positions. The service enforces them while it holds the space-row lock, and
integration tests cover them after add, delete, reorder and their races.

**Error mapping (T001)**:

| Error                                    | Result                                 |
| ---------------------------------------- | -------------------------------------- |
| `23514` on `space_photo_position_range`  | 409 `photo:limit-reached`              |
| `23505` on `space_photo_position_unique` | 500, logged at `error` (a service bug) |
| `55P03`                                  | `warn` `photo.lock_timeout`, then 500  |

## `photo_object_purge`

An outbox of storage objects to delete (R-7, ADR-0011 section 9). It covers both deleted photos and upload
intents.

| Column            | Type          | Null | Default             | Notes                                                                       |
| ----------------- | ------------- | ---- | ------------------- | --------------------------------------------------------------------------- |
| `id`              | `uuid`        | no   | `gen_random_uuid()` | PK                                                                          |
| `space_id`        | `uuid`        | no   |                     | No FK: the purge outlives the photo row. Used to build the keys             |
| `photo_id`        | `uuid`        | no   |                     | No FK, for the same reason                                                  |
| `reason`          | `text`        | no   |                     | CHECK `IN ('deleted', 'abandoned_upload')`                                  |
| `due_at`          | `timestamptz` | no   |                     | `now()` for deletes; `now() + 1 hour` for upload intents                    |
| `attempts`        | `integer`     | no   | `0`                 | Incremented by every sweep claim                                            |
| `last_attempt_at` | `timestamptz` | yes  |                     | Set by the claim; it is also the lease (10 minutes). `NULL` = never claimed |
| `created_at`      | `timestamptz` | no   | `now()`             |                                                                             |

**Constraints and indexes**:

- `photo_object_purge_reason_valid` CHECK.
- `photo_object_purge_attempts_nonnegative` CHECK `(attempts >= 0)`.
- UNIQUE `(photo_id)`: one pending purge per photo. An upload's intent and a later delete never coexist, because
  the insert transaction removes the intent.
- Index `photo_object_purge_due_idx` on `(due_at)` for the sweep.

**(T001)** Rules for the rows:

- **Claim.** The sweep claims rows with a lease and never holds a transaction open across storage calls.
- **Intent removal.** The photo-insert transaction deletes its intent only if the sweep has not claimed it, and
  it must delete exactly one row (query paths below).
- **Known failure after the put.** The upload sets `due_at = now()` on its intent. There is no inline storage
  delete.

## Storage objects (not a table)

| Key                                       | Content                                                              | Written by   | Removed by      |
| ----------------------------------------- | -------------------------------------------------------------------- | ------------ | --------------- |
| `spaces/{spaceId}/{photoId}/card.webp`    | exactly 640 × 480, cover-crop from the centre, WebP q75, no metadata | upload, seed | the purge sweep |
| `spaces/{spaceId}/{photoId}/display.webp` | fits inside 1600 × 1600, never enlarged, WebP q80, no metadata       | upload, seed | the purge sweep |

- Objects are written with `Content-Type: image/webp`, and a key's bytes never change.
- No original is stored (ADR-0011, Consequences).
- The bucket is private. Access is only through presigned GET URLs that carry the signed
  `response-cache-control: private` and a `response-expires` equal to the URL's own expiry (ADR-0011 section 5).

## Derived values (computed on read, never stored)

- **Cover**: the row with `position = 1` (spec Key Entities).
- **`altText`**: the `description`, or `"<space.name> photo <position>"` when there is none (FR-008, R-8).
- **Photo count**: `count(*)` for the space, shown as "n of 10".
- **URLs**: presigned per response, with one `now` and the windowed signing date. `photoUrlsExpireAt` is the
  window's expiry.

## State and lifecycle

```text
(owner picks file) ─▶ guards + admission ─▶ multer (≤ 10 MiB) ─▶ validate + process (semaphore)
                                                                  │ reject (4xx): nothing stored
                                                                  ▼
                               insert intent (due now + 1 h) ─▶ put card + display
                                                                  │
                     tx: lock_timeout; space FOR UPDATE with owner_id; count < 10?
                       │ yes: delete own unclaimed intent (exactly 1 row), insert at n + 1 ──▶ ADDED
                       │ no / 404 / intent claimed: roll back; set intent due_at = now() (sweep purges)
ADDED ──describe / reorder──▶ ADDED
ADDED ──delete──▶ tx: delete row, renumber (one UPDATE), insert purge (due now) ─▶ next sweep ─▶ objects gone
```

## Query paths

| Use                                      | Query                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Owner list                               | `space` by id and `owner_id` (404 otherwise), then `space_photo WHERE space_id ORDER BY position`                                                                                                                                                                                                                                                                   |
| Listing detail (renter)                  | the existing published-only space read, then the same photo read                                                                                                                                                                                                                                                                                                    |
| Search page (renter)                     | the existing search query plus `LEFT JOIN space_photo p ON p.space_id = s.id AND p.position = 1`                                                                                                                                                                                                                                                                    |
| Writers (add, describe, reorder, delete) | `SET LOCAL lock_timeout = '5s'`; `SELECT … FROM space WHERE id = $1 AND owner_id = $2 FOR UPDATE`; then the photo rows (ADR-0009 section 9.3)                                                                                                                                                                                                                       |
| Reorder                                  | `UPDATE space_photo p SET position = v.pos, updated_at = now() FROM (VALUES …) v(id, pos) WHERE p.id = v.id AND p.space_id = $1` (one statement)                                                                                                                                                                                                                    |
| Renumber after delete                    | `UPDATE space_photo SET position = position - 1 WHERE space_id = $1 AND position > $2` (one statement)                                                                                                                                                                                                                                                              |
| Intent removal (in the add tx)           | `DELETE FROM photo_object_purge WHERE photo_id = $1 AND reason = 'abandoned_upload' AND last_attempt_at IS NULL`; anything but exactly 1 row rolls back                                                                                                                                                                                                             |
| Sweep claim (own short tx)               | `UPDATE photo_object_purge SET attempts = attempts + 1, last_attempt_at = now() WHERE id IN (SELECT id FROM photo_object_purge WHERE due_at <= now() AND (last_attempt_at IS NULL OR last_attempt_at < now() - interval '10 minutes') ORDER BY due_at LIMIT 100 FOR UPDATE SKIP LOCKED) RETURNING …`, then commit, delete the keys, then `DELETE` each finished row |

## ADR-0009 section 9.3 table additions (done in T001)

| Writer         | Code                          | Space row                      | Seat locks | After the space row                                           |
| -------------- | ----------------------------- | ------------------------------ | ---------- | ------------------------------------------------------------- |
| Photo add      | `SpacePhotosService.add`      | `FOR UPDATE` (with `owner_id`) | none       | count, delete the upload intent, insert the photo at n + 1    |
| Photo describe | `SpacePhotosService.describe` | `FOR UPDATE` (with `owner_id`) | none       | update the photo                                              |
| Photo reorder  | `SpacePhotosService.reorder`  | `FOR UPDATE` (with `owner_id`) | none       | read the ids, one `UPDATE` of all positions                   |
| Photo delete   | `SpacePhotosService.remove`   | `FOR UPDATE` (with `owner_id`) | none       | delete the photo, one `UPDATE` renumber, insert the purge row |

The intent insert and the purge sweep lock only `photo_object_purge` rows, so they are not in the table.
